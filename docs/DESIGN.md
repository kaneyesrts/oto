# oto — дизайн и архитектура

Рабочее название: **oto** (音, «звук»). Плеер, который собирает музыку из разных
источников в одну библиотеку и делает из прослушивания визуальное событие.

## 1. Стек и почему именно он

| Слой | Технология | Почему |
|---|---|---|
| Ядро | **Rust** (Tauri 2) | аудио, декодирование, FFT, библиотека, лирика, статистика, хоткеи, трей, окна |
| Аудио | `rodio` (cpal + symphonia) | MP3/FLAC/OGG/Opus/AAC/ALAC/WAV, ресемплинг, seek |
| Анализ | `realfft` | спектр, энергия по полосам и детект битов для визуала, 60 к/с |
| Теги | `lofty` | теги, обложки, встроенная лирика (USLT / ©lyr / LYRICS) |
| База | SQLite (`rusqlite`, bundled) | библиотека, кэш лирики, история прослушиваний |
| Интерфейс | **Svelte 5** в WebView2 (Chromium) | лучшая графика: WebGL-шейдеры, SVG-фильтры, `backdrop-filter` |

Почему не «чистый» Rust GUI (egui / iced / Slint): уровень визуала из референсов
(liquid glass с преломлением, размытие по фону, шейдерные градиенты, плавная типографика)
в них пришлось бы писать с нуля на wgpu. В Tauri вся логика на Rust, а рисует
Chromium. Liquid glass делается фильтром SVG `feDisplacementMap` в `backdrop-filter`,
а он работает только в Chromium, то есть как раз в WebView2.

## 2. Источники музыки: что реально, а что нет

Всё звучит через **один аудиодвижок на Rust**. Каждый источник отдаёт ему PCM или поток,
поэтому визуализатор, эквалайзер, статистика и синхронизация лирики работают одинаково
для любого источника. Это главный архитектурный принцип.

| Источник | Как | Ограничения |
|---|---|---|
| Локальные файлы | `rodio` + `lofty` | нет, готово |
| Яндекс Музыка | неофициальное API (токен OAuth), прямые ссылки на mp3/aac | API неофициальное и может сломаться. Есть синхронная лирика |
| SoundCloud | `client_id` из веб-клиента, progressive mp3 / HLS | регистрация приложений закрыта, поэтому тоже неофициально |
| Spotify | `librespot` (Rust, Spotify Connect) отдаёт PCM в наш движок | **только Premium**. Web API для новых приложений сильно урезан |

Трейт `Source` в Rust: `search`, `resolve(track) -> поток`, `library()`, `lyrics(track)`.
Треки из разных источников **склеиваются** по ISRC, а без него по нормализованным
«артист + название» с допуском по длительности ±3 с. В библиотеке остаётся одна
запись, у которой несколько способов проиграть.

## 3. Лирика: каскад источников и подгонка под музыку

Порядок (первый **синхронный** текст побеждает, а простой текст держим про запас):

1. `.lrc` рядом с файлом (то же имя)
2. встроенная в теги (LRC внутри USLT тоже распознаётся)
3. кэш в SQLite (сюда же сохраняются ручные правки смещения)
4. LRCLIB `/api/get` (артист, трек, альбом, длительность), затем `/api/search` (нечёткий поиск)
5. *(этап 2)* Яндекс Музыка, затем другие источники

Подгонка:
- **Автосдвиг синхронного текста.** Текст часто снят с другой версии трека
  (длиннее интро, радио-версия). Rust один раз декодирует трек, строит огибающую
  энергии в вокальной полосе (300–3400 Гц), ищет пики (onsets) и перебором смещения
  (±12 с) и масштаба (0.97–1.03) максимизирует совпадение начал строк с пиками.
  Сдвиг применяется только при явном выигрыше над нулевым, иначе текст не трогаем.
- **Оценочная синхронизация простого текста.** Если синхронного нет нигде, строки
  раскладываются по участкам с вокалом пропорционально длине строки. В интерфейсе
  такой текст помечен «≈ авто». Это честнее, чем статичная простыня.
- **Ручная подстройка**: ±0.25 с кнопками или колесом, сохраняется для трека.
- *(этап 3, опционально)* точное выравнивание по словам через `whisper` (локально).

## 4. Визуальная система

Правила, чтобы не скатиться в «AI-слоп»:
- никаких фиолетово-синих градиентов по умолчанию: цвет берётся **из обложки**
  (k-means в Rust, 5 цветов), каждый трек окрашивает интерфейс по-своему;
- одна выразительная гарнитура на тему, крупная типографика, много воздуха;
- эффекты привязаны к звуку, а не просто «красиво крутятся»: бас толкает частицы,
  атаки дают вспышку, громкость меняет интенсивность градиента;
- движение пружинное (spring), без линейных CSS-переходов в ключевых местах;
- `prefers-reduced-motion` и ручной тумблер «спокойный режим».

### Темы (меняют вид, а не только цвета)
| Тема | Настроение | Отличия раскладки |
|---|---|---|
| **Noir** | тёмная, плотная, акцент из обложки (реф. Melo) | три колонки, сайдбар, правая панель «сейчас играет» |
| **Mist** | светлая розово-туманная, матовое стекло (реф. 1) | плавающие карточки на пейзажном градиенте |
| **Liquid** | liquid glass с преломлением поверх живого фона из обложки | панели-капсулы, mica/acrylic у окна Windows |
| **Paper** | швейцарская типографика, белое и чёрное, ноль декора | огромные заголовки, сетка, без обложек в списках |

### Режим лирики
Фон: шейдерный mesh-градиент из цветов обложки, реагирует на громкость.
Частицы: WebGL, бас даёт импульс, бит даёт вспышку. Строки: активная крупная и
заливается по ходу пения, соседние размыты пропорционально расстоянию, прокрутка
на пружине. Клик по строке перематывает на неё.

## 5. Трей, виджет, оверлей, хоткеи

- **Трей**: подсказка «Артист — Трек». ЛКМ открывает стеклянный flyout у трея
  (обложка, прогресс, управление, мини-спектр), закрывается при потере фокуса.
  ПКМ открывает меню (трек, ⏯ ⏮ ⏭, ♥, виджет, оверлей, выход).
- **Виджет**: одно окно, два слоя:
  - *рабочий стол*: под всеми окнами;
  - *оверлей*: поверх всех окон, режим «сквозь клики».

  Стили: компакт / лирика-строка / спектр. Настройки: прозрачность, размытие,
  масштаб, эффекты (свечение, частицы, спектр), позиция запоминается.
- **Глобальные хоткеи** (настраиваются): Ctrl+Alt+Space ⏯, Ctrl+Alt+→/← трек,
  Ctrl+Alt+↑/↓ громкость, Ctrl+Alt+L ♥, Ctrl+Alt+W виджет, Ctrl+Alt+O сквозь клики.
- **SMTC Windows** (`souvlaki`): медиаклавиши и системная плашка громкости
  с обложкой.

## 6. Статистика (то, что реально интересно смотреть)
Время за сегодня / неделю / всё время, топ треков и артистов за период,
теплокарта «час × день недели», серия дней подряд, доля пропущенных треков,
«открытие недели» (артист, который вырос сильнее всех). Прослушивание засчитывается
от 30 с или 50 % трека.

## 7. Что сознательно НЕ делаем (фичи ради фич)
- соцсети, «поделиться в сторис»: нет ценности в десктопном плеере;
- 3D-обложки и «вращающиеся пластинки»: красиво 5 секунд, мешает всегда;
- AI-плейлисты на старте: без истории прослушиваний будут мусором.
  Вернёмся, когда накопится статистика;
- встроенный магазин тем: сначала 4 сильные темы.

## 8. Этапы
1. **Ядро**: локальная библиотека, движок, спектр, лирика (файлы + LRCLIB + автосдвиг),
   4 темы, режим лирики, трей / flyout, виджет / оверлей, хоткеи, SMTC, статистика.
2. Яндекс Музыка, SoundCloud, склейка треков, очередь из разных источников.
3. Spotify через librespot, эквалайзер, кроссфейд / gapless, whisper-выравнивание.
